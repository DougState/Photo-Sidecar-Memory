## Problem Statement

A trained retoucher and commercial photographer (Ringling College, Nikon D800) needs a tool to automatically sort and route RAW photos into workflow channels based on post-process intent. Current workflow: manually rating files in Adobe Bridge with stars and color labels. Bridge doesn't learn, doesn't understand creative intent, and doesn't prepare outputs. Existing AI culling tools (Aftershoot, Imagen AI) target wedding photographers with proprietary SaaS models and focus on keep/reject decisions. None encode a photographer's post-process intent or route files toward their likely creative destination.

## What Makes This Cool

This isn't a photo quality sorter. It's a post-process intent engine. It answers: "What does this RAW file want to become?" A CMYK canvas print? An Instagram square? A base layer for a multi-layer PSD composite? A product catalog hero shot?

The taste.md file is the product. A human-readable, version-controlled specification of your creative judgment. Diffable. Forkable. Shareable. Other photographers can import your taste profile the same way developers import dotfiles.

The learning curve demo (40% accuracy to 85% over 3 shoots) proves the agent actually learns your eye. That's an AI story that makes hiring managers and photographers alike say "whoa."

## Constraints

- Must work with Nikon D800 NEF files (36MP RAW)
- Must use ImageMagick for output transforms (author's core expertise, blog content at dougstate.com)
- Must use Python (FastAPI/SQLite experience, already on resume)
- Must work as a CLI tool (no mandatory GUI for v1)
- Vision API costs must be manageable. Target: single-pass multi-channel scoring (~$0.02-0.05 per image for ALL channels in one API call, not per-channel). A 100-image shoot should cost under $5.
- Must produce a GitHub-ready portfolio piece with README, demo, and blog post

## Premises

1. taste.md encodes **post-process intent**, not just aesthetic preference. It describes what you're looking for in a RAW file based on what you'd do with it next (CMYK print, Instagram crop, PSD composite layer, commercial product shot). Confirmed by author's Ringling retouching background.

2. Vision APIs can judge a thumbnail's potential for a specific output channel (print-worthy landscape, social-media-ready composition, commercial product viability) when given the right prompt context from taste.md.

3. Three distinct use cases with different anchor weights:
   - **Commercial:** find diamonds fast, route to print/web/catalog pipelines
   - **Social:** identify Instagram-ready compositions from a shoot
   - **Hobbyist:** community-shared taste profiles as inputs (v2+ — no import/merge mechanism in v1)

4. The app has portfolio value AND personal use value AND potential commercial value. Immediate goal is a working GitHub project demonstrating full stack: ImageMagick, Python, AI, photography domain expertise.

5. The output pipeline matters as much as the sorting: product photos need digital downsizing, landscapes need CMYK profile matching for canvas prints, social needs cropping/resizing. The agent routes AND prepares.

## Cross-Model Perspective

An independent Claude subagent reviewed the problem cold and contributed:

- **Coolest version not considered:** taste.md as a changelog. A feedback loop watches PSD saves, diffs RAW vs. final output, and proposes amendments to taste.md. Version-controlled taste evolution becomes diffable, forkable, shareable like a dotfile. - **Key technical insight:** The D800 stores a full-res JPEG inside each NEF file. Use rawpy to extract embedded previews instead of decoding the full 36MP RAW. This makes ingest nearly instant.

- **50% exists:** libraw + rawpy + ImageMagick handles ingest, thumbnail extraction, and EXIF reading. The novel 50% to build: vision-API scoring (thumbnail + taste.md context to channel assignment with confidence) + routing logic (directory structures, ICC profiles, per-channel ImageMagick pipelines).

## Architecture (V1)

```
bridge-assist/
  taste.md              # Human-readable taste specification
  bridge_assist/
    __init__.py
    cli.py              # Click-based CLI entry point
    ingest.py           # rawpy NEF preview extraction + EXIF manifest
    score.py            # Vision API scoring (thumbnail + taste.md context)
    route.py            # Symlink routing + ImageMagick output transforms
    report.py           # Markdown report generation with inline thumbnails
  .bridge-assist/       # Per-project working directory (gitignored)
    previews/           # Extracted JPEG previews from NEFs
    manifest.json       # EXIF data + file metadata
    scores.json         # Vision API scoring results
    routes/             # Channel directories with symlinks
      print-cmyk/
      instagram/
      composite-base/
      web-catalog/
```

### taste.md Spec

```markdown
# Taste Profile: Doug Wagner

## Channels

### print-cmyk
- Intent: Full-resolution canvas print, gallery submission
- Signals: Strong tonal range, sharp detail, clean composition, landscape orientation preferred
- Output: Apply CMYK ICC profile (USWebCoatedSWOP), 300 DPI, no crop
- Confidence threshold: 0.75

### instagram
- Intent: Social media post, square or 4:5 crop
- Signals: Strong subject, visual impact at small size, good negative space for text overlay
- Output: Center crop to 1:1 or 4:5, sRGB, 1080px wide, sharpen for screen
- Confidence threshold: 0.6

### composite-base
- Intent: Base layer for multi-layer PSD composite
- Signals: Clean background, interesting texture, good separation between subject and background
- Output: Full resolution TIFF, preserve all detail, no color correction
- Confidence threshold: 0.7

### web-catalog
- Intent: Product catalog hero shot, e-commerce listing
- Signals: Clean product isolation, even lighting, detail visibility, neutral background
- Output: sRGB, multiple sizes (2400px, 1200px, 600px), web-optimized JPEG quality 85
- Confidence threshold: 0.65

## Global Preferences
- Favor compositions with strong foreground-to-background depth
- Prefer images where the subject fills 40-60% of the frame
- Weight macro detail shots higher for product/catalog channels
- Penalize obvious motion blur unless artistic intent is clear
```

### CLI Commands

```bash
# 1. Ingest: extract previews and EXIF from a folder of NEFs
bridge-assist ingest ./raw-folder

# 2. Score: run vision API scoring against taste.md channels
#    Single API call per image scores ALL channels simultaneously.
bridge-assist score --taste ./taste.md

# 3. Route: create channel directories with symlinks to originals + derivative outputs
#    Per-channel thresholds from taste.md apply. --threshold overrides ALL channels.
#    Images CAN land in multiple channels (a great landscape might be both print-cmyk AND instagram).
bridge-assist route
bridge-assist route --threshold 0.7   # Override all per-channel thresholds
bridge-assist route --dry-run         # Show what would be routed, create nothing
bridge-assist route --clean           # Remove previous routing outputs before re-routing

# 4. Report: generate markdown summary with thumbnails and scores
bridge-assist report --output ./sort-report.md
```

### Configuration

```bash
# API key via environment variable (preferred) or config flag
export BRIDGE_ASSIST_API_KEY=sk-...
bridge-assist score --api-key sk-...   # Alternatively

# Validate taste.md before scoring (checks required fields, channel names, thresholds)
bridge-assist validate --taste ./taste.md
```

### Command Dependencies

Commands must run in order: `ingest` -> `score` -> `route` -> `report`. Each is idempotent (safe to re-run). `score` will error if `ingest` has not been run (no manifest.json). `route` will error if `score` has not been run (no scores.json).

### Multi-Channel Assignment

A single image can land in multiple channels. A stunning landscape might score above threshold for both `print-cmyk` and `instagram`. Each channel directory gets a symlink to the original NEF plus its own derivative outputs (CMYK TIFF, Instagram crop JPEG, etc.). The `report` command shows all channel assignments per image.

### Routing Output Structure

Each channel directory contains:
- **Symlinks to original NEFs** (the RAW file stays in place, never moved/copied)
- **Derivative files** generated by ImageMagick from the **extracted preview JPEG** (not the full RAW). For v1, all derivatives are preview-quality proofs. Full-RAW processing (e.g., true CMYK TIFF from NEF via dcraw/libraw delegate) is deferred to v2 when the routing accuracy is validated. This avoids the ImageMagick NEF delegate dependency entirely for v1.
- Example: `IMG_1234_cmyk_proof.jpg` (CMYK simulation from preview), `IMG_1234_ig_1080.jpg` (Instagram crop from preview)

### JSON Response Parsing

Vision APIs may return conversational preamble or markdown fences around JSON. Parsing strategy:
1. Use `response_format: {"type": "json_object"}` if the API supports it (Claude tool_use, OpenAI JSON mode)
2. Fallback: regex extract the first `[...]` array from the response text
3. On parse failure: retry once with a stricter prompt ("Return ONLY valid JSON, no other text")
4. On second failure: skip image, log error

### Offline Commands

`route` and `report` work entirely from cached `scores.json` and `manifest.json`. They never call the vision API. Only `score` calls the API. Re-running `score` after updating taste.md re-scores all images (full re-score). Use `score --only-unscored` to skip already-scored images.

### Error Handling

- **Corrupt NEF / extraction failure:** Log warning, skip file, continue ingest. Report lists skipped files.
- **Vision API error (malformed response, rate limit, auth failure):** Retry once with backoff. On second failure, log error, skip image, continue. Report lists unscored images.
- **Missing API key:** `score` exits immediately with clear error message and instructions.
- **Malformed taste.md:** `validate` (and implicitly `score`) exits with specific error (missing field name, line number).
- **ICC profile not found:** `route` warns and skips CMYK conversion for that image, routes without transform.

### Vision API Prompt Template (single-pass, all channels)

One API call per image. Scores all channels simultaneously.

```
You are evaluating a photograph for multiple creative workflow channels.

PHOTOGRAPHER'S GLOBAL PREFERENCES:
{global_preferences}

EXIF DATA:
- Camera: {camera_model}
- Lens: {lens}
- Focal length: {focal_length}mm
- Aperture: f/{aperture}
- ISO: {iso}
- Shutter: {shutter_speed}

Score this image for ALL of the following channels. For each, rate suitability 0.0 to 1.0.

CHANNELS:
{for each channel: name, intent, signals}

Return JSON array:
[
  {"channel": "print-cmyk", "confidence": 0.82, "reasoning": "strong tonal range, sharp detail..."},
  {"channel": "instagram", "confidence": 0.45, "reasoning": "landscape orientation limits social impact..."},
  ...
]
```

**Confidence calibration guide** (included in taste.md for reference):
- 0.9-1.0: "I would definitely process this for this channel"
- 0.7-0.9: "Strong candidate, worth reviewing"
- 0.5-0.7: "Maybe, depends on the rest of the shoot"
- Below 0.5: "Probably not, unless nothing better exists"

## Open Questions

1. **Which vision API?** Claude vision vs. GPT-4V vs. Gemini Pro Vision. Need to test quality and cost on actual D800 thumbnails. Claude's structured output is attractive. **Day 1 task: test 10 images on each API, compare channel assignment quality.**
2. **Embedded preview resolution:** D800 NEFs have a full-res embedded JPEG, but is it good enough for aesthetic judgment? Need to verify with rawpy extraction. **Day 1 task: extract 5 previews, compare to manual decode.**
3. **ICC profile workflow:** Does ImageMagick's CMYK conversion match what Photoshop produces? May need to validate against known good prints. **Mitigation: for v1, ICC conversion is optional. Log a warning if profile is missing, route without transform. Validate against Photoshop in week 2.**
